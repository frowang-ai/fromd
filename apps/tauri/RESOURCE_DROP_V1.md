# Resource drop v1

Windows resource drop uses the existing HTML5 `File` path and the same `resourcePacket` → fixed binary IPC → coordinator binding flow as the paste and menu actions. The Tauri window sets `dragDropEnabled: false`; Tauri documents that this is required on Windows when the frontend needs HTML5 drag and drop because the default WebView2 handler is replaced by Tauri's internal drag-drop handler.

Rendered mode uses the public ProseMirror `EditorView.posAtCoords` result captured at the drop gesture and inserts the managed inline image/link at that exact PM position. The coordinator freezes the matching document session before validation and carries the original PM state and mode through the async operation. If the owner, generation, mode, PM state, or position changes, or resource validation fails, the document and selection remain unchanged. The position is never guessed from a later selection.

The drop area decides between importing a resource and opening a document. External file drops on the sidebar (macOS, including the narrow drawer) or on the sidebar, web titlebar and tab bar (Windows) open `.md` / `.markdown` / `.txt` through the native open queue instead of importing; the empty editor panel (no page) also opens. Everything else keeps this resource path: a `.md` dropped into the body is still a managed attachment link, and the scroller's side and bottom margins count as the body — the coordinates are clamped into the ProseMirror content box so `posAtCoords` returns the nearest line position instead of `null`. The macOS tab bar rejects file drops with a hint to use the sidebar. See [desktop behavior](DESKTOP_FEEDBACK.md#系统打开方式与拖入打开) for the open rules.

Source mode currently rejects file drops with an explicit message because the textarea does not provide a safe coordinate mapping in this unit. The user can switch to rendered mode or use the existing source paste/menu flow. Directory drops, non-file drags, drops outside the editor and the open areas, and SVG image drops are rejected without importing or executing anything. SVG remains available through the explicit attachment action.

The app-level capture guard prevents protected external `Files` dragover/drop navigation outside the editor and while source/busy states are active, routes open-area drops to the document open path (`dropEffect='copy'`, "松开以打开" feedback), and leaves rendered PM drag handling and internal tab/text drags to their existing handlers; the tab reorder handlers ignore external files. A refused target keeps `dropEffect='none'`, so the browser never dispatches `drop` there; the refusal reason (macOS tab bar, source mode, busy, non-body area) is therefore shown while hovering in one floating hint beside the cursor, which takes no layout space. Browser tests use synthetic `File`/`DataTransfer` events, plus one Chromium CDP `Input.dispatchDragEvent` case with an on-disk synthetic file that checks where the browser really fires `drop`. A real Explorer-to-WebView2 drop, native Tauri event delivery, and Windows shell behavior remain local-machine validation items.
