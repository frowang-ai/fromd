# macOS 安装说明

## 下载

到 [Releases](https://github.com/frowang-ai/fromd/releases/latest) 下载对应芯片的安装包：

| Mac | 下载 |
| --- | --- |
| Apple 芯片（M 系列，含 M1、M2、M3、M4 及后续型号） | `fromd_<版本>_aarch64.dmg` |
| Intel 处理器 | `fromd_<版本>_x64.dmg` |

不确定是哪种：点左上角苹果菜单 → **关于本机**，「芯片」写 Apple M 开头就选 **aarch64**（也叫 ARM64），「处理器」写 Intel 就选 **x64**（也叫 x86_64）。MacBook Air 也有这两类，按芯片选择，不按机型名称猜。

同一页还有 `fromd-<版本>-aarch64.app.zip` 和 `fromd-<版本>-x86_64.app.zip`，内容和 DMG 一样，只是换成了压缩包，二选一即可。

最低系统版本 macOS 11.0。

## 校验文件

先确认下载页是本项目的 [GitHub Releases](https://github.com/frowang-ai/fromd/releases)，安装包和 `SHA256SUMS.txt` 来自**同一版本**。在下载目录打开「终端」，用实际下载的文件名替换下例：

```sh
shasum -a 256 fromd_0.5.2_aarch64.dmg
```

输出的 SHA-256 应和 `SHA256SUMS.txt` 中**相同文件名**那一行一致。哈希能确认下载文件是否与该发布物一致，不能代替来源判断。不一致就不要打开，删除这份下载后重新下载；仍不一致请反馈。

## 安装

1. 打开 DMG，把 `fromd.app` 拖到窗口中的 **Applications / 应用程序** 文件夹，等待复制完成。
2. 推出 DMG，在访达的 **应用程序** 中打开 `/Applications/fromd.app`。不要直接运行 DMG 中的副本。

用 `.app.zip` 的话，双击解压，再把 `fromd.app` 移入 `/Applications`，之后从「应用程序」打开。

## 第一次打开

**当前已发布的 v0.5.2 包按未签名、未公证分发。** 仓库新的打包配置已启用免费 **ad-hoc 签名**，这项改动尚未发行，不会改变已下载的旧包。ad-hoc 用于校验签名后应用内容是否改变，不提供 Apple 认证的开发者身份；它不是 Developer ID 签名，也不等于苹果公证，不能保证 Gatekeeper 直接放行。

### 提示「无法验证开发者」或「Apple 无法检查是否包含恶意软件」

确认来源和哈希后：

1. 先在「应用程序」里双击 fromd，看到提示后点「完成」或「取消」。
2. 打开 **系统设置 → 隐私与安全性**，往下找到关于 fromd 的提示，点 **仍要打开**。较旧 macOS 对应 **系统偏好设置 → 安全性与隐私 → 通用**。
3. 按系统提示确认。按钮名称及是否允许例外因系统版本和管理策略而异。

### 提示「fromd 已损坏，无法打开」

这条提示可能来自下载/解压损坏、签名无效或下载隔离检查，不能仅凭提示断定原因：

1. 先按上文核对官方来源和 SHA-256。删除下载的 DMG/ZIP，重新下载并校验，再把新副本复制到 `/Applications`。
2. 若仍出现同样提示，且确认信任这份来源与文件，可以手动在「终端」执行以下命令，**只删除已安装 fromd 的下载隔离标记**：

   ```sh
   xattr -dr com.apple.quarantine "/Applications/fromd.app"
   ```

   `-d` 删除指定的 `com.apple.quarantine` 属性，`-r` 仅递归这个 app 内的文件；不会清空其他扩展属性，也不会关闭全局 Gatekeeper。此操作会移除这份 app 的下载隔离检查，不能修复实际损坏、恶意内容或无效签名，不能作为“应用安全”的证明。应用和安装器不会自动执行它。
3. 再从「应用程序」打开；如果仍失败，不要反复移除标记或自行重签。请反馈 macOS 版本、芯片、包名、SHA-256 与完整提示（不附私人笔记）。

如果只是找不到「仍要打开」，同样先重新下载、校验并确认已安装到 `/Applications`，再按上述隔离标记说明自行决定。若系统明确提示包含恶意软件或会损坏电脑，停止打开并反馈，不沿用此例外步骤。

## 检查更新

在原生菜单「fromd → 检查更新…」检查最新正式版。左下角提示新版本后，点击「前往下载更新」打开本仓库的 Release 下载页，选择对应芯片的 DMG。

正常退出应用，让最后正文、名称和阅读位置保存完成，再把新 `fromd.app` 拖进「应用程序」替换旧版。旧应用仍名为 `frowd.app` 时，先退出它，再放入 `fromd.app`；确认新版本里的资料完整后可以移除旧 app，保留下面的数据目录。应用不会自行静默替换，也不会主动退出。两个 app 使用同一资料库，不能同时打开同一资料目录。

## 数据保存在哪里

| 内容 | 位置 |
| --- | --- |
| 草稿、页面、图片和附件 | `~/Library/Application Support/com.frowang.frowd.tauri.v1` |
| 你保存的 `.md` 文件 | 你自己选择的位置 |

从 frowd Tauri 0.5.2 改名升级到 fromd，仍沿用此目录中的 `drafts.sqlite`、`resources/objects` 和阅读设置；替换应用不会重建文稿数据库。

想备份草稿，退出程序后复制这个文件夹即可。在访达里按 `⇧⌘G`，粘贴上面的路径就能打开。

## 快捷键

macOS 上用 `⌘` 代替 Windows 的 `Ctrl`，例外：

- 查找替换是 `⌥⌘F`（`⌘H` 留给系统的隐藏窗口）
- 切换页面是 `⌃Tab` / `⌃⇧Tab`
- 打开链接是 `⌘` + 点击，普通点击是编辑

## 卸载

退出 fromd，把「应用程序」里的 `fromd.app` 移到废纸篓。

这样不会删除草稿。想连草稿一起删，再删除上面的数据文件夹，未保存成 `.md` 的内容会一起删除，无法恢复。
