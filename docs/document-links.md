# 链接点击（0.4.3）

正文和表格中的链接普通单击即可执行以下动作。浮层中的地址文字使用同一规则；原复制、铅笔编辑和移除链接入口保留。Shift选区、拖选文字及输入法组合输入不触发打开。

| 目标 | 行为 |
| --- | --- |
| `http://` / `https://` | 默认浏览器打开网页 |
| 本机文件，包括Word、PDF和Markdown | 在资源管理器中显示并尽可能选中，不启动文件默认应用 |
| 本机文件夹 | 在资源管理器中进入该文件夹 |
| `./附件/计划.docx` 等相对路径 | 相对于该篇Markdown文件所在目录解析；切换笔记和另存为后使用对应的最新位置 |
| 未保存草稿中的相对路径 | 提示先保存为Markdown或改用绝对路径 |
| 缺失/不可访问目标、浏览器/目录调用失败 | 在应用内显示错误，保留正文 |

支持`file:///C:/目录/文件`、Windows带盘符路径（含桌面工具常用的`/C:/目录/文件`形式）和相对路径。URL编码只解码一次，带空格、中文、`#`和`%`的文件名可用`%20`、`%23`、`%25`表示。文件链接的查询和片段不参与定位文件。纯`#锚点`保留原编辑器/浏览器行为，不交给系统。

本轮限定本机路径；网络共享、Windows设备路径、缺盘符的根路径以及其他应用协议不接入。文件不存在时明确报错，不根据扩展名猜测目标类型。没有文件默认应用打开入口：`openPath`只用于已解析并确认的目录，普通文件均调用`showItemInFolder`。

## 归属与调用

- `packages/editor/src/writingLinks.js`：从编辑模型读取原始目的地，区分点击与选区动作，带会话归属发出事件。组件不依赖Electron，也不放宽Milkdown的DOM链接消毒。此行为由`linkNavigation`显式开启，不改变独立编辑器默认行为。
- `App.vue`核对当前文档/代次/可用状态后，经固定的`desktop.openLink(id, href)`发送请求；浮层的旧会话地址不能套用新笔记位置。
- `main/documentLinks.js`负责分类、解析、检查目标和调用系统；基准目录取自主进程的文档记录，前端不能指定cwd或任意shell命令。IPC沿用来源窗口与frame校验。

## 验证入口

- `npm test`中的`tests/document-links.test.mjs`：协议、路径与编码、草稿提示、文件/目录分类、缺失与失败处理；包括exe/lnk/url文件只定位的约束。
- `npm run test:desktop`中的`tests/links.desktop.spec.mjs`：真实Electron正文/表格/浮层点击，经真实preload/IPC和文件检查，验证文件定位、目录进入、切换/另存路径、错误、复制编辑、选区与过期浮层。
- 桌面用例仅替代最终OS调用及对话框返回值，避免启动默认浏览器、资源管理器或文档软件；没有用真实用户笔记作样本。OS集成的实际检查与版本成品结果见`VALIDATION.md`。
- 共享编辑器改动沿用`npm run test:editor`检查原编辑行为。
